# Kth Smallest Amount With Single Denomination Combination

## Problem

- **Name:** Kth Smallest Amount With Single Denomination Combination
- **Difficulty:** Hard
- **Category:** Binary Search, Math, Number Theory, Inclusion-Exclusion

## Core Pattern

### Main Algorithmic Pattern

**Binary Search on Answer + Inclusion-Exclusion**

### Recognition Cues

Look for problems where:

- We need the **kth smallest value** satisfying a numerical condition.
- A value is valid if it is divisible by **at least one** of several numbers.
- Multiple conditions can overlap.
- The number of denominations/sets is small enough to enumerate subsets.
- `k` is very large, making direct generation impossible.

### Why the Pattern Applies

For a candidate value `x`, we can determine how many valid amounts are `<= x`.

If that count is at least `k`, then `x` may contain the kth answer.

Therefore the problem becomes:

> Find the smallest `x` such that `count(x) >= k`.

This monotonic property allows binary search.

The challenge is calculating `count(x)` without iterating over every amount. Inclusion-exclusion counts multiples of the denominations while removing overlaps.

## Intuition

Imagine the denominations are:

`[2, 3, 5]`

The valid amounts are numbers divisible by at least one denomination.

For a target `x`:

- `x // 2` numbers are divisible by 2.
- `x // 3` numbers are divisible by 3.
- `x // 5` numbers are divisible by 5.

Simply adding these counts double-counts numbers such as 6, 10, 15, etc.

So inclusion-exclusion is used:

- Add multiples of individual denominations.
- Subtract multiples of every pair's LCM.
- Add multiples of every triple's LCM.
- Continue alternating.

For a subset of denominations, every number divisible by all denominations in that subset is divisible by their LCM.

Therefore:

`count(x) = Σ sign * (x // LCM(subset))`

Once `count(x)` is available, binary search finds the smallest `x` for which the count reaches `k`.

## Brute Force

### Idea

Generate positive integers starting from 1.

For each integer, check whether it is divisible by at least one denomination.

Count valid numbers until the kth valid amount is found.

### Complexity

If the answer is `A`, this requires approximately `O(A * n)` work.

Since `k` can be extremely large, `A` can also be extremely large.

### Why It Is Inefficient

The kth amount cannot realistically be generated one by one when `k` is up to billions.

The key improvement is to **count how many valid values exist up to a candidate answer instead of generating them**.

## Optimal Solution

### Key Observations

1. The answer is at most:

   `min(coins) * k`

   because the first `k` multiples of the smallest denomination are all valid.

2. For any target `x`, the number of valid amounts `<= x` can be calculated using inclusion-exclusion.

3. `count(x)` is monotonic:
   - If `count(x) >= k`, every larger value also has at least `k` valid amounts.
   - If `count(x) < k`, every smaller value also has fewer than `k`.

4. Therefore binary search can be applied.

5. `len(coins) <= 15`, so there are at most:

   `2^15 - 1 = 32767`

   non-empty subsets.

### Data Structures Used

- A list of `(LCM, sign)` pairs for all non-empty subsets.
- Binary search over the numerical answer range.

### Algorithm Explanation

First enumerate every non-empty subset of denominations.

For each subset:

1. Calculate the LCM of all denominations in that subset.
2. Determine the subset size.
3. Assign:
   - `+1` when the subset size is odd.
   - `-1` when the subset size is even.

Then define `count_amounts_le(x)`:

For every stored `(LCM, sign)`:

`sign * (x // LCM)`

is added to the total.

This gives the number of values `<= x` divisible by at least one denomination.

Finally, binary search for the smallest `x` whose count is at least `k`.

## Algorithm

1. Let `n = len(coins)`.
2. Enumerate every non-empty subset from `1` to `2^n - 1`.
3. For each subset:
   - Start its LCM at 1.
   - For every selected denomination, update the LCM.
   - Count the selected denominations.
   - Assign `+1` for odd subset size and `-1` for even subset size.
4. Store each subset's LCM and sign.
5. Set:
   - `low = 1`
   - `high = min(coins) * k`
6. While `low <= high`:
   - Calculate `mid`.
   - Calculate how many valid amounts are `<= mid`.
7. If the count is at least `k`:
   - `mid` is a possible answer.
   - Search the left half.
8. Otherwise:
   - Search the right half.
9. Return the smallest valid value.

## Complexity

Let `n = len(coins)`.

There are `2^n - 1` non-empty subsets.

### Precomputation

Each subset examines up to `n` denominations:

**Time:** `O(n * 2^n)`

### Binary Search

Each count operation examines every subset:

**Time per count:** `O(2^n)`

The binary search requires:

`O(log(k * min(coins)))`

iterations.

Therefore:

**Total Time:** `O(n * 2^n + 2^n * log(k * min(coins)))`

**Space:** `O(2^n)`

With `n <= 15`, this is practical.

## Edge Cases

- **One denomination**
  - The answer is simply `coins[0] * k`.

- **Denominations containing duplicates**
  - Inclusion-exclusion still handles overlapping sets correctly.

- **One denomination being a multiple of another**
  - Example: `[2, 4]`.
  - Multiples of 4 are already included among multiples of 2.
  - Inclusion-exclusion removes the duplicate contribution.

- **Highly overlapping denominations**
  - Example: `[2, 3, 6]`.
  - LCM-based inclusion-exclusion correctly handles all overlaps.

- **Large `k`**
  - Direct generation is impossible.
  - Binary search avoids depending linearly on `k`.

- **Answer near the upper bound**
  - `min(coins) * k` safely contains the answer.

## Alternative Approaches

### Brute Force Enumeration

Generate every positive integer and check divisibility.

- Simple.
- Too slow for large `k`.

### Priority Queue / Multiway Merge

Generate multiples from each denomination and merge them while eliminating duplicates.

This can conceptually find the kth value, but may require processing up to `k` values and is therefore unsuitable for very large `k`.

### Inclusion-Exclusion + Binary Search

This is the preferred approach.

It transforms the problem from:

> Generate the kth valid amount.

into:

> Count valid amounts up to `x`, then binary-search `x`.

## Python Tips

### `math.gcd`

Python's `math.gcd` provides an efficient GCD implementation.

LCM can be calculated as:

`a * b // gcd(a, b)`

### Bitmask Subsets

For `n` elements, integers from `1` through `(1 << n) - 1` represent all non-empty subsets.

For element `j`:

`(mask >> j) & 1`

determines whether that element belongs to the subset.

### Avoid Floating Point

All calculations can remain integer-based.

This is particularly important because the answer can be very large.

### Monotonic Binary Search

The important structure is:

- `count(mid) >= k` → move left.
- `count(mid) < k` → move right.

This is the standard "first true" binary-search pattern.

## Interview Discussion

An interviewer may ask:

### Why can binary search be used?

Because `count(x)` is monotonic.

If at least `k` valid amounts exist up to `x`, then at least `k` also exist up to every value greater than `x`.

### Why use LCM?

For a subset of denominations, a number is divisible by every denomination in that subset exactly when it is divisible by their LCM.

### Why does inclusion-exclusion work?

Adding individual multiples counts every valid number once per denomination that divides it.

Subtracting pairwise intersections removes duplicate counting.

Adding triple intersections restores values removed too many times.

The alternating signs continue for larger subsets.

### Why is `min(coins) * k` a valid upper bound?

Every multiple of the smallest denomination is valid.

Therefore the first `k` multiples provide `k` valid amounts, so the kth valid amount cannot exceed `min(coins) * k`.

### What determines feasibility of this solution?

The number of denominations must be small enough to enumerate subsets.

With `n <= 15`, at most 32767 subsets exist.

## Personal Takeaways

1. **When asked for the kth value, look for a way to count values `<= x`.**
2. **If the count is monotonic, binary search on the answer.**
3. **For "divisible by at least one" conditions, think inclusion-exclusion.**
4. **For intersections of divisibility conditions, think LCM.**
5. **A small `n` often means exponential subset enumeration is intentional and acceptable.**
