# Make Lexicographically Smallest Array by Swapping Elements

## Problem

- **Problem:** Make Lexicographically Smallest Array by Swapping Elements
- **LeetCode:** 2948
- **Difficulty:** Medium
- **Category:** Array, Sorting, Greedy, Connected Components

Given an array `nums` and a `limit`, two elements can be swapped whenever their absolute difference is at most `limit`.

The goal is to return the lexicographically smallest array obtainable through any number of valid swaps.

---

## Core Pattern

### Main Pattern

**Sort + threshold-based connected-group identification**

The important observation is that the values can be sorted and partitioned into groups.

If consecutive values in sorted order differ by at most `limit`, they belong to the same connected component.

For each connected component:

1. Collect its values.
2. Collect their original indices.
3. Sort the original indices.
4. Put the smallest value at the smallest index, the next-smallest value at the next index, etc.

### Recognition Cues

Look for problems involving:

- Swapping elements under a value-based restriction.
- Repeated swaps.
- A condition such as `abs(a - b) <= limit`.
- Asking for the lexicographically smallest arrangement.
- Transitive relationships between elements.
- A need to determine which elements can eventually reach one another.

---

## Intuition

The first important question is not:

> Which individual swaps should I perform?

Instead ask:

> Which elements can eventually be rearranged among the same set of positions?

Consider:

    values = [1, 3, 5]
    limit = 2

`1` and `5` cannot directly swap because:

    |1 - 5| = 4 > 2

However:

    |1 - 3| = 2
    |3 - 5| = 2

Therefore:

    1 <-> 3 <-> 5

Through repeated swaps, all three elements can be rearranged among their original positions.

This means the problem is really about identifying connected components.

Sorting reveals these components efficiently.

If sorted values are:

    1, 3, 5, 8, 9

and:

    limit = 2

then:

    3 - 1 = 2
    5 - 3 = 2
    8 - 5 = 3
    9 - 8 = 1

Therefore the groups are:

    [1, 3, 5]
    [8, 9]

Once a group is identified, all its elements can effectively be permuted among that group's original indices.

To minimize the whole array lexicographically, assign the smallest values to the smallest available indices.

---

## Brute Force

### Idea

Repeatedly search for any pair of elements whose difference is at most `limit`, try swaps, and keep track of the lexicographically smallest reachable array.

### Complexity

The number of possible swap sequences can grow exponentially.

Even checking many possible states is infeasible for `n = 100000`.

### Why It Is Inefficient

The problem does not require us to discover an actual sequence of swaps.

We only need to determine the connected components created by the swap rule.

---

## Optimal Solution

### Key Observations

1. Sort `(value, original_index)` pairs by value.
2. A new group begins whenever the difference between two adjacent sorted values exceeds `limit`.
3. Every element inside one group can be rearranged among the group's original positions.
4. For lexicographical minimization:
   - sort the group's values;
   - sort the group's original indices;
   - assign values to indices in corresponding order.

### Data Structures

- Sorted list of `(value, original_index)` tuples.
- Temporary list containing the current group.
- Sorted list of original indices.

No graph or explicit Union-Find structure is required.

---

## Algorithm

1. Pair every value with its original index.

   Example:

       nums = [1, 5, 3, 9, 8]

   becomes:

       [(1, 0), (5, 1), (3, 2), (9, 3), (8, 4)]

2. Sort the pairs by value:

       [(1, 0), (3, 2), (5, 1), (8, 4), (9, 3)]

3. Scan the sorted pairs.

4. Continue the current group while:

       current_value - previous_value <= limit

5. When the difference exceeds `limit`, finish the current group.

6. For every group:
   - extract the values;
   - extract the original indices;
   - sort the original indices;
   - place the sorted values into the sorted indices.

7. Process the final group.

8. Return the modified array.

---

## Complexity

Let `n = len(nums)`.

### Time Complexity

Sorting all `(value, index)` pairs:

    O(n log n)

Sorting the indices of each group:

    O(n log n)

in the worst case.

Therefore:

    O(n log n)

### Space Complexity

The sorted pairs and temporary group structures require:

    O(n)

Therefore:

    O(n) space.

## Edge Cases

### 1. Single element

    nums = [5]
    limit = 1

No swaps are possible or necessary.

Result:

    [5]

### 2. No elements can be connected

If every adjacent sorted gap is greater than `limit`, every element forms its own group.

The original array remains unchanged.

### 3. All elements belong to one group

If every adjacent sorted difference is at most `limit`, all elements belong to one connected component.

The entire array can be rearranged by assigning sorted values to sorted original indices.

### 4. Transitive connectivity

This is the most important edge case.

    values = [1, 3, 5]
    limit = 2

Although `1` and `5` cannot directly swap, they belong to the same component through `3`.

### 5. Duplicate values

Duplicate values naturally remain in the same group whenever their surrounding values satisfy the limit condition.

Python's tuple sorting handles equal values safely.

### 6. Boundary difference

If:

    abs(a - b) == limit

the swap is allowed.

Therefore the grouping condition must be:

    <= limit

not:

    < limit

## Alternative Approaches

### Union-Find / DSU

Another valid approach is to treat every element as a node and connect elements whose values can be linked through the threshold.

After constructing connected components, sort the values and indices within each component.

However, explicit DSU is unnecessary here because sorting gives the connected components directly.

### Sorting-Based Grouping

Preferred approach for this problem.

Advantages:

- Simpler.
- Less code.
- No parent/rank structure.
- Directly exposes the mathematical structure.
- `O(n log n)`.

## Interview Discussion

### Why is comparing adjacent sorted values enough?

Because if:

    a1 <= a2 <= a3 <= ... <= ak

and every adjacent difference satisfies:

    ai+1 - ai <= limit

then every adjacent pair provides a valid connection.

Therefore all values in that range belong to the same connected component.

If a gap occurs:

    ai+1 - ai > limit

then no value on the left can connect to a value on the right.

The sorted gap therefore separates two components.

### Why can the values within a component be arbitrarily rearranged?

The allowed swaps create a connected graph.

Repeated swaps along paths allow elements to move through the connected component.

Thus the component's values can be permuted among its original positions.

### Why assign the smallest value to the smallest index?

Lexicographical order is determined by the earliest differing position.

Therefore, whenever a component can choose which value occupies which position, placing the smallest available value at the smallest index gives the best possible prefix.

## Personal Takeaways

1. **Repeated swaps often mean connected components.**
2. **A direct swap restriction does not necessarily describe the final reachability.**
3. **Sort first when connectivity depends on numerical distance.**
4. **For lexicographical minimization, place the smallest values at the smallest reachable indices.**
5. **Before reaching for Union-Find, check whether sorting turns the implicit graph into adjacent-gap groups.**
