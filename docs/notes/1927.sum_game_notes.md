# Sum Game

## Problem

- **Name:** Sum Game
- **Difficulty:** Medium
- **Category:** Math / Game Theory

## Core Pattern

- **Main algorithmic pattern:** Mathematical game-state reduction.
- **Recognition cues:** Two players alternately choose unknown values, the objective compares two fixed groups, and the choices affect only the final difference.
- **Why the pattern applies:** The individual choices do not need to be simulated. The game can be reduced to the known-sum difference and the imbalance in the number of unknown digits on each side.

## Intuition

An experienced engineer should first avoid simulating every possible digit choice.

Split the string into two halves and compute:

- the known-digit sum of each half;
- the number of `?` characters in each half.

If the total number of `?` characters is odd, Alice gets the decisive extra move and can force a win.

When the number of `?` characters is even, the game is determined by whether the current sum difference exactly matches the amount that can be compensated by the question marks. Each pair of question marks contributes a maximum relevant difference of 9, giving the losing condition:

`sum1 - sum2 = 9 * (q2 - q1) / 2`

Therefore Alice wins exactly when this equality does not hold.

## Brute Force

### Idea

Simulate the game recursively:

1. Find a `?`.
2. Try every digit from 0 through 9.
3. Alternate between Alice and Bob.
4. Determine whether each player has a winning strategy.

### Complexity

This has exponential game-state complexity because each `?` can take 10 possible values and the number of game states grows rapidly.

### Why it is inefficient

The actual game has a much simpler mathematical invariant, so exploring individual digit assignments is unnecessary.

## Optimal Solution

### Key observations

1. Only the two half-sums matter.
2. Only the counts of `?` on each side matter.
3. If the total number of `?` characters is odd, Alice wins.
4. Otherwise, Bob can force a tie exactly when:

   `s1 - s2 = 9 * (q2 - q1) / 2`

5. Therefore the answer is the negation of that equality.

### Data structures used

Only four integer variables:

- `s1`
- `s2`
- `q1`
- `q2`

### Algorithm explanation

Scan the first half and calculate its known sum and question-mark count.

Scan the second half and calculate its known sum and question-mark count.

If the total number of question marks is odd, return `True`.

Otherwise compare the existing sum difference against the compensating difference created by the question marks. If they are unequal, Alice can force a win.

## Algorithm

1. Let `half = n / 2`.
2. Initialize both half sums to zero.
3. Initialize both question-mark counts to zero.
4. Process the first half:
   - increment `q1` for `?`;
   - otherwise add the digit to `s1`.
5. Process the second half similarly for `q2` and `s2`.
6. If `(q1 + q2)` is odd, return `True`.
7. Otherwise return whether:
   `s1 - s2 != 9 * (q2 - q1) / 2`.

## Complexity

- **Time Complexity:** `O(n)`
- **Space Complexity:** `O(1)`

The input must be inspected to determine the sums and question-mark counts, so `O(n)` time is optimal.

## Edge Cases

- No question marks.
- All characters are question marks.
- An odd number of question marks.
- Equal known sums but different question-mark counts.
- Different known sums where the question marks exactly compensate for the difference.
- A single pair of question marks.

## Alternative Approaches

### Recursive minimax

Correct in principle but exponentially expensive.

### Explicit game simulation

Also unnecessary because the game outcome depends only on aggregate counts and sums.

### Mathematical reduction

The chosen solution is the preferred approach because it reduces the game to constant extra state and a single final condition.

## Python Tips

- `int(num[i])` is sufficient because the known characters are digits.
- Counting with integer variables keeps the implementation `O(1)` extra space.
- When using integer division, verify that the numerator is guaranteed to be divisible before using `//`.
- Here `(q1 + q2)` is even in the branch using `// 2`, so `q2 - q1` is also even and the division is exact.

## Interview Discussion

An interviewer may ask:

- **Why don't we simulate the game?**
  - Explain that only aggregate sum differences and question-mark counts affect the final outcome.

- **Why does an odd number of question marks immediately imply Alice wins?**
  - Explain the alternating-turn parity and Alice's decisive extra move.

- **Why is the factor 9 present?**
  - A digit can range from 0 to 9, so the largest possible contribution from one unknown digit is 9.

- **Can this be solved in one pass?**
  - Yes. The two halves can be processed using the index to determine which aggregate each character belongs to.

## Personal Takeaways

1. Look for a mathematical invariant before simulating a two-player game.
2. For fixed-size groups, aggregate sums and counts may completely describe the game state.
3. Turn parity can sometimes determine the winner immediately.
4. When using integer division, prove divisibility rather than assuming it.
5. A game problem can have an `O(n)` mathematical solution even when naive minimax is exponential.
