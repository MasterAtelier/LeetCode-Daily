# Stone Game (LeetCode 877)

## Problem

- **Difficulty:** Medium
- **Category:** Dynamic Programming, Game Theory, Minimax

---

## Core Pattern

### Pattern
Minimax Dynamic Programming using **Score Difference DP**

### Recognition Cues

Look for:

- Two players playing optimally
- Players alternately pick from either end
- Need to determine winner instead of exact score
- Both players have perfect information

### Why this pattern applies

Instead of tracking both players' scores independently, we track the **maximum score difference** the current player can achieve over the opponent.

---

## Intuition

Whenever it's your turn, you have exactly two choices:

1. Take the left pile.
2. Take the right pile.

After your move, the opponent becomes the current player.

Therefore,

Your gain =
```
Value picked - Opponent's best achievable advantage
```

This naturally leads to a recursive minimax formulation.

---

## Brute Force

### Idea

Recursively try both choices for every move.

### Complexity

Time:
```
O(2^n)
```

Space:
```
O(n)
```

### Why inefficient

Many subarrays are solved repeatedly.

---

## Optimal Solution

### Key observations

- Only the current interval `(i, j)` matters.
- The current player's identity is implicit.
- Tracking score difference removes the need to store:
  - current turn
  - player scores

### State

```
dp(i, j)
```

Maximum score difference current player can obtain from interval `[i, j]`.

### Transition

```
max(
    piles[i] - dp(i+1, j),
    piles[j] - dp(i, j-1)
)
```

### Base Case

```
i == j
```

Return that pile.

---

## Algorithm

1. Define DP on interval `(i, j)`.
2. If only one pile remains, return its value.
3. Compute:
   - take left
   - take right
4. Return the better option.
5. Player 1 wins if final score difference is positive.

---

## Complexity

### Time

```
O(n²)
```

There are `n²` intervals.

### Space

```
O(n²)
```

For memoization.

---

## Edge Cases

- One pile
- Two piles
- Equal valued piles
- Large pile values
- Maximum input size

## Alternative Approaches

### Bottom-up DP

Same complexity.

### Mathematical Observation

For LeetCode 877 specifically, Player 1 always wins because the number of piles is even and the total sum is odd. Therefore, the accepted one-line solution is:

```python
return True
```

However, this does **not** generalize to Stone Game II/III or Predict the Winner.

## Personal Takeaways

- Many game DP problems reduce to score difference.
- Interval DP often uses `(i, j)` as the complete state.
- Avoid storing unnecessary state such as player turns.
- Minimax recursion becomes simple after defining the correct DP state.
- Always look for opportunities to compress state.
