# Length of Longest Subarray With at Most K Frequency

## Problem

- **Name:** Length of Longest Subarray With at Most K Frequency
- **Problem Number:** 2958
- **Difficulty:** Medium
- **Category:** Sliding Window

## Core Pattern

**Variable-Size Sliding Window with Frequency Map**

### Recognition Cues

Look for:

- "Longest subarray"
- "At most K"
- A contiguous subarray/window
- A constraint on the frequency of values
- The goal is to maximize the window length

### Why the Pattern Applies

The problem asks for the longest contiguous range where every value occurs at most `k` times.

As the right pointer expands the window, the window can become invalid only when the newly added value exceeds its allowed frequency. We can then move the left pointer forward until the constraint is restored.

This gives a linear-time solution because both pointers move only forward.

## Intuition

Think of `[left, right]` as the largest valid window ending at the current `right`.

1. Add the new element at `right`.
2. Track its frequency.
3. If its frequency exceeds `k`, the window is invalid.
4. Move `left` forward and decrement frequencies until the window becomes valid again.
5. The resulting window is the longest valid window ending at this `right`.
6. Keep the maximum length seen.

The important observation is that **only `nums[right]` can newly violate the constraint**. Before adding `nums[right]`, the previous window was valid.

## Brute Force

### Idea

Enumerate every possible subarray and count the frequency of its elements. Keep the longest subarray in which every frequency is at most `k`.

### Complexity

A straightforward implementation can take `O(n^2)` subarrays, with additional work to calculate frequencies, potentially resulting in `O(n^3)` time.

An improved brute-force approach can incrementally maintain frequencies for each starting index, giving `O(n^2)` time.

### Why It Is Inefficient

There are `O(n^2)` possible contiguous subarrays, while the sliding-window solution processes each element with only forward pointer movements.

## Optimal Solution

### Key Observations

- The valid condition is: every value in the current window has frequency `<= k`.
- Adding an element can only make the frequency of that element invalid.
- Once invalid, moving `left` forward can only decrease frequencies.
- Therefore, the window can be restored using a single left pointer.
- Every element enters the window once and leaves the window at most once.

### Data Structures Used

- **Frequency map:** stores the number of occurrences of each value currently inside the window.
- **Two pointers:** `left` and `right` define the current window.

### Algorithm Explanation

For every `right`:

1. Increment the frequency of `nums[right]`.
2. While the frequency of `nums[right]` is greater than `k`:
   - Decrement the frequency of `nums[left]`.
   - Move `left` one position right.
3. Calculate the current valid window length.
4. Update the maximum answer.

## Algorithm

1. Initialize an empty frequency map.
2. Set `left = 0` and `ans = 0`.
3. Iterate `right` from `0` to `n - 1`.
4. Increment the frequency of `nums[right]`.
5. While `freq[nums[right]] > k`:
   - Decrement the frequency of `nums[left]`.
   - Increment `left`.
6. Update `ans` with `right - left + 1`.
7. Return `ans`.

## Complexity

### Time Complexity

**O(n)**

The `right` pointer moves from left to right exactly once. The `left` pointer also moves forward at most `n` times.

Therefore, the total number of pointer movements is `O(n)`.

### Space Complexity

**O(n)** in the worst case.

The frequency map can contain up to `n` distinct values.

## Edge Cases

- **Single element:** The answer is `1` when `k >= 1`.
- **All elements unique:** With `k = 1`, the entire array is valid.
- **All elements identical:** The answer is at most `k`.
- **`k` larger than every possible frequency:** The entire array is valid.
- **`k = 1`:** The problem becomes finding the longest subarray containing only unique values.
- **Repeated value at the right boundary:** The window must shrink until that value's frequency is valid again.
- **Multiple left-pointer movements:** A single newly added value can require removing several elements before its frequency becomes `<= k`.

## Alternative Approaches

### Hash Map + Sliding Window

This is the chosen optimal approach.

- Time: `O(n)`
- Space: `O(n)`
- Best fit because the constraint is based on frequencies inside a contiguous window.

### Brute Force + Frequency Map

For every starting index, expand the ending index while maintaining frequencies.

- Time: `O(n^2)`
- Space: `O(n)`
- Simpler conceptually but unnecessary for the required constraints.

### Prefix/Offline Frequency Approaches

These are possible in specialized settings but are more complicated and do not provide an advantage here. The constraint depends dynamically on the current contiguous window, making sliding window the natural solution.

## Python Tips

- `defaultdict(int)` is convenient when incrementing counts without explicitly checking whether a key exists.
- `freq[value] += 1` and `freq[value] -= 1` make the frequency updates concise.
- `range(len(nums))` is appropriate when the right pointer needs the element index.
- The window length is always `right - left + 1`.
- Do not remove zero-frequency keys unless needed; it is unnecessary for correctness.

## Interview Discussion

### Follow-up: Why is the solution O(n) despite the nested while loop?

Because `left` never moves backward. Across the entire algorithm it can move at most `n` times, while `right` also moves exactly `n` times.

### Follow-up: Why do we only check `freq[nums[right]]`?

The window was valid before `nums[right]` was inserted. The only frequency that can have changed from valid to invalid is the frequency of the newly inserted value.

### Follow-up: What changes if the condition is "at most K distinct values"?

Instead of checking the frequency of the newly added value, maintain the number of distinct keys in the window and shrink while that count exceeds `k`.

### Follow-up: What if the condition is "exactly K"?

A common technique is:

`exactly K = atMost(K) - atMost(K - 1)`

when counting subarrays rather than maximizing a single window length.

## Personal Takeaways

- **Longest + contiguous + constraint → immediately consider sliding window.**
- Maintain a clear **window invariant** and restore it whenever it breaks.
- A nested `while` does not automatically mean `O(n^2)`; check whether the pointer moves monotonically.
- Ask which part of the state can become invalid when a new element enters the window.
- Frequency maps are a natural companion to sliding windows when the constraint depends on occurrence counts.
