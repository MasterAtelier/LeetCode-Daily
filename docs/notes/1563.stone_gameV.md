# Stone Game V

## Problem

- **Problem:** Stone Game V
- **LeetCode:** 1563
- **Difficulty:** Hard
- **Category:** Dynamic Programming / Prefix Sum / Monotonic Pointer Optimization

## Core Pattern

### Main algorithmic pattern

**Interval DP + prefix sums + monotonic partition boundary.**

The interval DP normally considers every partition point `k` inside `[i, j]`. The optimized solution observes that, for a fixed left endpoint `i`, the largest partition boundary satisfying `left_sum <= right_sum` moves monotonically to the right as `j` increases.

### Recognition cues

Look for:
- A contiguous interval that must be split.
- A score determined by the two partition sums.
- A transition to another interval.
- A naive interval DP with an additional partition loop.
- Prefix sums for `O(1)` range sums.
- A partition boundary that moves monotonically as an endpoint changes.

### Why the pattern applies

For fixed `i`, let `p` be the largest partition index satisfying:

`sum(i..p) <= sum(p+1..j)`.

Because all stone values are positive, increasing `j` cannot move this boundary backward. Therefore one forward-moving pointer replaces a binary search for every interval.

## Intuition

`dp[i][j]` is the best score obtainable from interval `[i, j]`.

For each split:
- If the left side is smaller, keep the left side and continue with the left interval.
- If the right side is smaller, keep the right side and continue with the right interval.
- If equal, either side may be retained.

The key optimization is avoiding a scan over all splits. For fixed `i`, as `j` increases, the valid partition boundary only moves forward.

`left_best` and `right_best` aggregate the transition values:
- `left_best[i][j]` captures the best `left_sum + dp[i][k]`.
- `right_best[i][j]` captures the best `right_sum + dp[k][j]`.

Thus the transition becomes constant time after advancing the monotonic pointer.

## Brute Force

Try every partition for every interval and recursively solve the retained side.

- **Time:** `O(n^3)` with memoization.
- **Space:** `O(n^2)`.
- Inefficient because every one of the `O(n^2)` states scans `O(n)` partitions.

## Optimal Solution

### Key observations

1. Prefix sums give constant-time interval sums.
2. For fixed `i`, the valid partition boundary is monotonic as `j` increases.
3. A single pointer `p` can therefore replace repeated binary searches.
4. `left_best` and `right_best` aggregate all relevant transitions on each side.
5. For fixed `i`, `p` advances at most `O(n)` times.

### Algorithm

Process `i` from right to left. For each `i`, initialize `p = i - 1`.

For each `j` from `i + 1` to `n - 1`:

1. Compute `total = sum(i..j)`.
2. Advance `p` while the next partition still satisfies `2 * left_sum <= total`.
3. If `p >= i`, use `left_best[i][p]`.
4. If the partition at `p` is exactly balanced, also consider `right_best[p + 1][j]`.
5. If `p + 2 <= j`, consider `right_best[p + 2][j]` for the right-smaller region.
6. Store the result in `dp[i][j]`.
7. Add `total` to the best continuation and update `left_best` and `right_best`.

## Complexity

- **Time:** `O(n^2)`.
- **Space:** `O(n^2)`.

There are `O(n^2)` intervals. For each fixed `i`, the partition pointer only moves forward across all `j`, so its total movement is `O(n)`.

## Edge Cases

- `n == 1`: answer is `0`.
- `n == 2`: only one split exists.
- Equal-valued arrays: many balanced partitions can occur.
- Highly uneven values: the boundary can remain close to one side.
- Multiple balanced partitions: both retained-side transitions must be considered.
- Boundary intervals must avoid invalid auxiliary-table indices.

## Alternative Approaches

1. **Naive recursive:** exponential without memoization.
2. **Interval DP:** `O(n^3)`.
3. **Interval DP + binary search:** `O(n^2 log n)`, correct but not optimal.
4. **Monotonic pointer + interval DP:** `O(n^2)`, the submitted solution.

## Python Tips

- Use prefix sums instead of repeated slicing and `sum`.
- Keep the monotonic pointer outside the inner `j` loop.
- `list[list[int]]` is sufficient for these `O(n^2)` tables.
- `list[int]` type annotations are appropriate for modern Python.
- For complex optimized DP, compare against a small brute-force oracle during testing.

## Interview Discussion

### Why can binary search be removed?

For fixed `i`, increasing `j` can only move the largest partition satisfying `left_sum <= right_sum` forward because all values are positive.

### Why are positive values important?

The monotonic-boundary proof relies on interval sums increasing as endpoints expand. With arbitrary negative values, that property can fail.

### Why are `left_best` and `right_best` needed?

They aggregate many partition transitions so the algorithm does not rescan every split.

### Why consider both sides on equality?

When the two sums are equal, either side may be retained, so both continuations are valid.

## Personal Takeaways

1. Check whether a repeated binary-search boundary is monotonic across neighboring DP states.
2. Positive array values often provide useful monotonicity.
3. Auxiliary DP aggregates can eliminate an inner transition loop.
4. A correct `O(n^2 log n)` interval DP may still have an `O(n^2)` optimization.
5. Use brute-force differential testing on small random inputs for complicated DP optimizations.
