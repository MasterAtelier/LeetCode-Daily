# Removing Minimum and Maximum From Array

## Problem

* **Name:** Removing Minimum and Maximum From Array
* **LeetCode:** 2091
* **Difficulty:** Medium
* **Category:** Greedy / Array / Boundary Analysis

## Core Pattern

### Main Algorithmic Pattern

**Boundary enumeration / greedy choice among a constant number of strategies.**

The problem allows deleting elements only from either end of the array. Once the minimum and maximum indices are known, there are only three meaningful strategies:

1. Remove both from the left.
2. Remove both from the right.
3. Remove the earlier one from the left and the later one from the right.

### Recognition Cues

Look for problems where:

* Operations are restricted to array boundaries.
* Specific target elements must be removed.
* Removing an element also removes everything between that element and an array boundary.
* The objective is to minimize the number of operations/deletions.

### Why the Pattern Applies

The relative positions of the minimum and maximum completely determine the required deletion cost. There is no need to simulate deletions.

Once their indices are known, every optimal solution falls into one of three cases.

## Intuition

An experienced engineer should first identify the elements that actually matter.

Here, only the minimum and maximum values matter. Their values are irrelevant after their indices have been found.

Suppose:

* `left` = earlier index of min/max
* `right` = later index of min/max

Then visualize the array as:

```text
0 ........ left ........ right ........ n-1
          min/max       max/min
```

There are only three useful ways to remove both elements.

### Case 1: Everything from the left

We must remove through `right`.

Cost:

```text
right + 1
```

### Case 2: Everything from the right

We must remove through `left`.

Cost:

```text
n - left
```

### Case 3: Use both ends

Remove the prefix through `left`, then remove the suffix beginning at `right`.

Cost:

```text
left + 1 + n - right
```

The answer is the minimum of these three costs.

## Brute Force

### Idea

Repeatedly try deleting from the left or right until both the minimum and maximum have disappeared.

This creates many possible deletion sequences.

### Complexity

Potentially exponential in the number of deletion choices if explored naively.

### Why It Is Inefficient

The deletion process contains unnecessary state. We only need the original positions of the minimum and maximum.

The problem can therefore be reduced to three arithmetic calculations.

## Optimal Solution

### Key Observations

1. Find the minimum element's index.
2. Find the maximum element's index.
3. Order those indices as `left <= right`.
4. Evaluate the three possible deletion strategies.
5. Return the smallest cost.

### Data Structures Used

No additional data structures are required.

Only four integer variables are needed:

* minimum index
* maximum index
* left index
* right index

## Algorithm

1. Set the minimum and maximum indices to `0`.
2. Scan the array once.
3. Update the minimum index whenever a smaller value is found.
4. Update the maximum index whenever a larger value is found.
5. Let `left` be the smaller of the two indices.
6. Let `right` be the larger of the two indices.
7. Calculate:

   * `right + 1`
   * `n - left`
   * `left + 1 + n - right`
8. Return the minimum of those three values.

## Complexity

### Time Complexity

`O(n)`

The array is scanned once to find the minimum and maximum indices.

### Space Complexity

`O(1)`

Only a constant number of variables are used.

## Edge Cases

### Minimum and maximum are already at the two ends

Example:

```text
[1, 2, 3, 4, 5]
```

The minimum is at index `0` and maximum at index `4`.

Deleting from both ends removes them in two deletions.

### Minimum and maximum are adjacent

No special handling is required. The three formulas still work.

### Minimum appears before maximum

```text
left = min_idx
right = max_idx
```

### Maximum appears before minimum

```text
left = min_idx
right = max_idx
```

The normalization makes the ordering irrelevant.

### Duplicate values

The scan stores the first occurrence encountered because updates occur only when a strictly smaller/larger value is found.

The problem only requires removing a minimum and a maximum occurrence, so this remains valid.

### Two-element array

Both elements are necessarily the minimum and maximum. The answer is `2`.

## Alternative Approaches

### Sorting

Sorting can identify the minimum and maximum values, but then their original indices still need to be determined.

This is unnecessary and increases the time complexity to `O(n log n)`.

### Repeated deletion simulation

This directly models the operation but is unnecessary and potentially expensive.

### Direct index-based calculation

The submitted solution uses the optimal approach: find the two indices and evaluate three constant-time strategies.

## Python Tips

### Track indices directly

The tuple approach is valid:

```text
(value, index)
```

but the solution can be simplified by maintaining only `min_idx` and `max_idx`.

### `min()` and `max()`

Python makes the normalization concise:

```text
left = min(min_idx, max_idx)
right = max(min_idx, max_idx)
```

### Constant number of cases

When a problem has only a few possible structural strategies, explicitly calculating each one is often clearer than trying to simulate operations.

## Interview Discussion

An interviewer may ask:

### Why are there only three cases?

Because deleting only from the two ends means that both target elements can be removed either:

* entirely from the left,
* entirely from the right,
* or by using both ends.

There is no fourth structurally distinct strategy.

### Why do you use `left` for the right-only case?

If deleting only from the right, we must reach the target element that occurs first.

Therefore the number of deletions is:

```text
n - left
```

### Why is the mixed case `left + 1 + n - right`?

The left deletion removes indices `0 ... left`.

The right deletion removes indices `right ... n-1`.

These two deleted regions do not overlap, so their sizes can be added.

### Can this be done in one pass?

Yes. The minimum and maximum indices can be found in a single `O(n)` traversal.

## Personal Takeaways

1. When operations are restricted to array ends, think in terms of **boundaries**, not simulation.
2. Identify the few elements that actually matter before designing the algorithm.
3. Normalize important indices with `left` and `right`.
4. Enumerate all structurally distinct strategies when their number is constant.
5. Be careful about whether a boundary calculation should use the **leftmost** or **rightmost** target index.
