# 3348. Smallest Divisible Digit Product II

## Problem

- Difficulty: Hard
- Category: Greedy, Number Theory, String

## Core Pattern

Greedy suffix reconstruction with prime-factor accounting.

### Recognition Cues

- Lexicographically smallest number
- Product divisibility
- Huge numeric string
- Cannot brute-force increment numbers
- Digits contribute multiplicative prime factors

### Why this Pattern Applies

Instead of tracking the digit product directly, decompose it into the exponents of primes {2,3,5,7}. Scan from right to left to find the earliest position that can be increased, then greedily construct the smallest valid suffix.

## Intuition

The key observation is that only the prime factors {2,3,5,7} matter. Each digit contributes a fixed set of these factors. Maintain the accumulated contribution of the prefix, then determine the minimal suffix needed after increasing one digit.

## Brute Force

Increment the number until the digit product becomes divisible by `t`.

Time Complexity: Exponential / infeasible.

Why inefficient:

- Number can contain up to 10⁵ digits.

## Optimal Solution

### Key Observations

- Factorize `t`.
- Represent every digit by its prime contributions.
- Maintain prefix factor counts.
- Traverse from right to left.
- Increase the first possible digit.
- Construct the smallest feasible suffix.

### Data Structures

- Counter
- String
- Greedy reconstruction

## Algorithm

1. Factorize `t`.
2. Reject if factors other than {2,3,5,7} remain.
3. Compute prime counts for the current number.
4. If already valid and contains no zero, return it.
5. Scan from right to left.
6. Remove the current digit's contribution.
7. Try larger replacement digits.
8. Compute remaining required prime factors.
9. Build the lexicographically smallest suffix.
10. If impossible, increase the number length.

## Complexity

Time: O(n)

Space: O(n)

## Edge Cases

- Impossible prime factors
- Existing answer
- Zeros
- Length increase
- Empty required suffix
- Large inputs

## Alternative Approaches

- DFS with pruning
- Dynamic programming on exponent states
- Backtracking

These are slower or significantly more complex.

## Personal Takeaways

- Convert multiplicative constraints into additive exponent counts.
- Greedy suffix replacement is powerful for lexicographic minimization.
- Maintain prefix state to avoid recomputation.
- Separate factor accounting from reconstruction.
