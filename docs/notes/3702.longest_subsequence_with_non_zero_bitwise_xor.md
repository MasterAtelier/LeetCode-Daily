# 3702 - Longest Subsequence With Non-Zero Bitwise XOR

## Problem

- **Problem:** Longest Subsequence With Non-Zero Bitwise XOR
- **LeetCode:** 3702
- **Difficulty:** Medium
- **Category:** Array, Bit Manipulation
- **Primary Pattern:** XOR / Bit Manipulation Observation

---

## Core Pattern

### XOR Invariant / Mathematical Observation

The central observation is that the answer can only be:

- `n`
- `n - 1`
- `0`

where `n = len(nums)`.

### Recognition Cues

Look for:

- A subsequence whose XOR must satisfy a condition.
- XOR of the entire array.
- A requirement to maximize the number of retained elements.
- Ability to remove elements.
- XOR identities such as:
  - `x ^ x = 0`
  - `x ^ 0 = x`
  - `0 ^ x = x`

### Why the Pattern Applies

We want the longest possible subsequence.

Therefore, the first question should be:

> "Can I use the entire array?"

If the XOR of the entire array is non-zero, the answer is immediately `n`.

If the XOR is zero, we cannot use all `n` elements.

The next question is:

> "Can I remove exactly one element and make the XOR non-zero?"

If at least one element is non-zero, yes.

---

## Intuition

Think about the problem from the perspective of minimizing deletions.

We are not really searching for an arbitrary subsequence.

We are asking:

> What is the minimum number of elements I need to remove so that the XOR becomes non-zero?

### Case 1: Entire array has non-zero XOR

If:

    nums[0] ^ nums[1] ^ ... ^ nums[n-1] != 0

then the entire array is already a valid subsequence.

Therefore:

    answer = n

No longer subsequence exists because the original array already contains every element.

---

### Case 2: Entire array has XOR zero

Suppose:

    XOR(nums) = 0

If we remove an element `x`, the XOR of the remaining elements is:

    XOR(nums) ^ x

Since:

    XOR(nums) = 0

we get:

    0 ^ x = x

Therefore, if we remove a non-zero `x`, the remaining subsequence has XOR `x`, which is non-zero.

So if the array contains at least one non-zero element:

    answer = n - 1

---

### Case 3: Every element is zero

If:

    nums = [0, 0, ..., 0]

then every possible subsequence also has XOR zero.

Therefore, no valid non-empty subsequence exists.

    answer = 0

---

## Brute Force

### Idea

Enumerate every possible subsequence.

For every subsequence:

1. Calculate its XOR.
2. If the XOR is non-zero, consider its length.
3. Keep the maximum length.

There are `2^n` possible subsequences.

### Complexity

Time:

    O(2^n * n)

depending on how the XOR is calculated.

Even an optimized enumeration is still exponential.

### Why It Is Inefficient

The constraints allow:

    n <= 100000

Therefore, enumerating subsequences is completely infeasible.

The important step is recognizing that we do not need to search the subsequence space at all.

---

## Optimal Solution

### Key Observations

There are exactly three exhaustive cases.

### Case 1

    total_xor != 0

Return:

    n

### Case 2

    total_xor == 0
    AND
    every element == 0

Return:

    0

### Case 3

    total_xor == 0
    AND
    at least one element != 0

Remove one non-zero element.

The resulting XOR is:

    total_xor ^ x
    = 0 ^ x
    = x

Since `x != 0`, the resulting XOR is non-zero.

Therefore:

    answer = n - 1

---

## Algorithm

1. Initialize `xor_all = 0`.
2. XOR every element into `xor_all`.
3. If `xor_all != 0`, return `n`.
4. Check whether every element is zero.
5. If every element is zero, return `0`.
6. Otherwise return `n - 1`.

---

## Complexity

### Time Complexity

    O(n)

We traverse the array to calculate the XOR.

The additional `all()` check is another `O(n)` traversal.

Therefore:

    O(n) + O(n) = O(n)

### Space Complexity

    O(1)

Only a constant number of variables are used.

---

## Edge Cases

### Single non-zero element

    [5]

XOR is `5`, therefore:

    answer = 1

---

### Single zero

    [0]

There is no subsequence with non-zero XOR.

    answer = 0

---

### All zeros

    [0, 0, 0, 0]

Every subsequence has XOR zero.

    answer = 0

---

### XOR zero with non-zero elements

    [1, 2, 3]

Because:

    1 ^ 2 ^ 3 = 0

we cannot keep all three.

Remove `1`:

    2 ^ 3 = 1

Therefore:

    answer = 2

---

### XOR already non-zero

    [2, 3, 4]

    2 ^ 3 ^ 4 = 5

Therefore the entire array is valid:

    answer = 3

---

### Zeros mixed with non-zero values

    [0, 1, 1]

Total XOR:

    0 ^ 1 ^ 1 = 0

The array is not all zeros.

Remove one `1`:

    0 ^ 1 = 1

Therefore:

    answer = 2

---

## Alternative Approaches

### 1. Brute Force

Enumerate every subsequence.

- Time: exponential
- Not viable.

### 2. Dynamic Programming

One could track possible XOR values and maximum lengths.

However, this is unnecessary because the problem has a much stronger mathematical observation.

### 3. Optimal XOR Observation

Compute the XOR of the complete array and determine whether a non-zero element exists.

- Time: `O(n)`
- Space: `O(1)`
- Preferred solution.

## Python Tips

### XOR operator

Python uses:

    ^

for bitwise XOR.

Example:

    5 ^ 3

### `all()`

The expression:

    all(x == 0 for x in nums)

checks whether every element is zero.

It short-circuits as soon as a non-zero element is found.

### Boolean checks

This:

    if xor_all != 0:

is more explicit than:

    if xor_all:

Both are valid for integers.

For interview code, either is acceptable.

## Interview Discussion

An interviewer may ask:

### Why can't the answer be `n - 2`?

It can, but it is never necessary when the total XOR is zero and a non-zero element exists.

Removing exactly one non-zero element produces a non-zero XOR.

Therefore `n - 1` is always achievable.

---

### Why does removing a non-zero element work?

Because:

    total_xor = 0

and:

    remaining_xor = total_xor ^ removed_element

Therefore:

    remaining_xor = 0 ^ x = x

If `x != 0`, the remaining XOR is non-zero.

---

### Why is `n - 1` optimal?

Because:

- `n` is impossible since the XOR of the complete array is zero.
- `n - 1` is achievable by removing one non-zero element.

Therefore `n - 1` is optimal.

---

### Can we solve it in one pass?

Yes.

Instead of:

    xor_all = 0
    for x in nums:
        xor_all ^= x

    if all(x == 0 for x in nums):
        ...

we can simultaneously track whether a non-zero element exists.

This is not asymptotically better, because both versions are `O(n)`, but it reduces the number of passes.

---

## Personal Takeaways

1. When maximizing a subsequence length, first ask whether the entire array works.
2. XOR problems should immediately trigger the identities `x ^ x = 0` and `x ^ 0 = x`.
3. If the full solution fails by exactly one condition, investigate whether removing one element fixes it.
4. Prove achievability and optimality separately.
5. A short solution can still require a strong mathematical observation.

## Final Code

```python
class Solution:
    def longestSubsequence(self, nums: list[int]) -> int:
        xor_all = 0

        for x in nums:
            xor_all ^= x

        if xor_all != 0:
            return len(nums)

        if all(x == 0 for x in nums):
            return 0

        return len(nums) - 1
