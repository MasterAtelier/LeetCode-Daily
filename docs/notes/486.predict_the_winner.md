# Predict the Winner

## Problem

- **LeetCode:** 486
- **Difficulty:** Medium
- **Category:** Dynamic Programming, Minimax, Game Theory

---

## Core Pattern

**Minimax + Dynamic Programming (Score Difference DP)**

### Recognition Cues

Look for problems where:

- Two players play optimally.
- Players take turns.
- Choices are made from the ends of an array.
- Determine whether the first player can guarantee a win.
- The game has perfect information.

Instead of tracking both players' scores independently, track the **maximum score difference** the current player can achieve.

---

## Intuition

Initially, it's tempting to keep track of both players' scores during recursion.

However, after making a move, the opponent faces the exact same problem on the remaining subarray.

Therefore, instead of storing two scores, store only:

> "How much more can the current player score than the opponent?"

This transforms the problem into a much smaller DP state.

---

## Brute Force

### Idea

Recursively simulate every possible game.

State:

- left index
- right index
- player turn
- player A score
- player B score

### Complexity

Time: O(2ⁿ)

Space: O(n)

### Why inefficient?

The same subproblems are solved repeatedly.

---

## Optimal Solution

### Key Observation

Let

```
dp(i, j)
```

represent

> Maximum score difference (Current Player − Opponent)
> obtainable from nums[i...j].

If the player picks the left element:

```
nums[i] - dp(i+1, j)
```

If the player picks the right element:

```
nums[j] - dp(i, j-1)
```

Choose the better move.

---

## Algorithm

1. Define DP on interval `(i, j)`.
2. Base case:
   - Empty interval → 0
   - Single element → nums[i]
3. Compute:
   - Pick left
   - Pick right
4. Store the result in memoization.
5. Final answer is:

```
dp(0, n-1) >= 0
```

---

## Complexity

Time: **O(n²)**

Space:

- DP table: **O(n²)**
- Recursion stack: **O(n)**

---

## Edge Cases

- Single element
- Two elements
- Tie (Player 1 wins)
- Equal values
- Strict loss
- Large arrays

---

## Alternative Approaches

### 1. Brute Force Minimax

State includes scores and turn.

Time: O(2ⁿ)

---

### 2. Memoized Minimax (Large State)

Memoize:

```
(i, j, turn, scoreA, scoreB)
```

Correct but still inefficient due to enormous state space.

---

### 3. Bottom-Up DP

Fill intervals of increasing length.

Same recurrence.

Time: O(n²)

Space: O(n²)

## Personal Takeaways

- Minimax problems often become DP problems.
- Choosing the right DP state is the hardest part.
- Tracking score difference is often simpler than tracking two scores.
- Smaller state → dramatically better complexity.
- Memoization only helps when equivalent states repeat.
