# Find the Minimum and Maximum Number of Nodes Between Critical Points

## Problem

- **Name:** Find the Minimum and Maximum Number of Nodes Between Critical Points
- **LeetCode:** 2058
- **Difficulty:** Medium
- **Category:** Linked List

## Core Pattern

### Main Algorithmic Pattern

Single-pass linked-list traversal with constant-space tracking.

### Recognition Cues

Look for problems involving:

- Linked-list nodes whose properties depend on neighboring nodes
- Finding special/critical positions
- Minimum distance between special positions
- Maximum distance between special positions
- Problems where storing every matching position is unnecessary

### Why the Pattern Applies

A critical point depends only on three consecutive values:

- previous node
- current node
- next node

Therefore, while traversing the linked list, we only need to maintain the previous value.

Additionally:

- The minimum distance only needs the previous critical point.
- The maximum distance only needs the first and latest critical point.

Therefore, all critical-point positions do not need to be stored.

---

## Intuition

Think of critical points as important positions along a line.

Suppose the critical points occur at:

```text
2, 5, 9, 14
```

The minimum distance must be between adjacent critical points:

```
5 - 2 = 3
9 - 5 = 4
14 - 9 = 5

minimum = 3
```

The maximum distance is simply:

```
14 - 2 = 12
```

Therefore, while scanning:

1. Remember the first critical point.
2. Remember the previous critical point.
3. When another critical point appears:

- update the minimum distance using the previous critical point
- update the latest critical point
4. At the end:

- maximum distance = last critical point - first critical point

This gives a one-pass constant-space solution.

---

## Brute Force

### Idea

Traverse the linked list and store the index of every critical point.

For example:

```
critical positions = [2, 5, 9, 14]
```

Then:

- Calculate every adjacent difference to find the minimum.
- Calculate `last - first` for the maximum.

### Complexity

- Time: `O(n)`
- Space: `O(k)`

where `k` is the number of critical points.

### Why It Is Inefficient

Although the time complexity is still optimal, storing all critical-point positions is unnecessary.

The answer only requires:

- first critical point
- previous critical point
- latest critical point
- minimum distance

Therefore, `O(1)` extra space is sufficient.

---

## Optimal Solution

### Key Observations

1. A critical point must have both a previous and next node.
2. A local maximum satisfies:

```
previous < current > next
```
3. A local minimum satisfies:

```
previous > current < next
```
4. The minimum distance can only occur between consecutive critical points.
5. The maximum distance is between the first and last critical points.
6. Therefore, all critical-point indices do not need to be stored.

### Data Structures Used

No additional data structure is required.

Only scalar variables are maintained:

- current index
- previous value
- first critical index
- last critical index
- minimum distance

---

## Algorithm

1. Initialize the current index to `0`.
2. Initialize the first and last critical-point positions as unset.
3. Maintain the value of the previous node.
4. Traverse the linked list while the current node has a next node.
5. Starting from index `1`, determine whether the current node is:

- a local maximum, or
- a local minimum.
6. If it is a critical point:

- If another critical point has already been seen, calculate the distance from the previous critical point.
- Update the minimum distance.
- If this is the first critical point, record its index.
- Update the latest critical-point index.
7. Move to the next node.
8. If fewer than two critical points were found, return:

```
[-1, -1]
```
9. Otherwise:

```
minimum = minimum distance between consecutive critical points
maximum = last critical index - first critical index
```
10. Return `[minimum, maximum]`.

---

## Complexity

### Time Complexity

`O(n)`

The linked list is traversed once.

### Space Complexity

`O(1)`

Only a constant number of variables are maintained.

---

## Edge Cases

### No Critical Points

Return:

```
[-1, -1]
```

### Only One Critical Point

Return:

```
[-1, -1]
```

At least two critical points are required to form a distance.

### Exactly Two Critical Points

Both answers are identical:

```
[distance, distance]
```

### Multiple Critical Points

The minimum is calculated using consecutive critical points.

The maximum is calculated using the first and last critical points.

### Negative Values

The algorithm uses comparisons rather than assumptions about value ranges, so negative values work correctly.

### Critical Point at the Beginning or End

Impossible by definition because a critical point requires both a previous and next node.

---

## Alternative Approaches

### Store All Critical Indices

Traverse the list and store every critical index.

Then calculate:

```
minimum = minimum adjacent difference
maximum = last - first
```

Complexity:

- Time: `O(n)`
- Space: `O(k)`

This is simpler conceptually but uses unnecessary memory.

### Constant-Space Streaming

Track only:

- first critical point
- previous critical point
- latest critical point
- minimum distance

Complexity:

- Time: `O(n)`
- Space: `O(1)`

This is the preferred solution.

## Python Tips

### Chained Comparisons

Python allows:

```
prev < curr > next
```

which is equivalent to:

```
prev < curr and curr > next
```

Similarly:

```
prev > curr < next
```

represents a local minimum.

### Constant-Space State

When processing a sequence, ask:

> Do I really need to store every matching element, or can I summarize everything seen so far?

Here, the answer is the latter.

## Interview Discussion

### Follow-up: Why don't you store all critical points?

Because the minimum only depends on consecutive critical points and the maximum only depends on the first and last critical points.

### Follow-up: Why can't the minimum distance involve non-consecutive critical points?

If critical points occur at:

```
a < b < c
```

then:

```
c - a > b - a
c - a > c - b
```

Therefore, a minimum distance can only occur between adjacent critical points.

### Follow-up: Can this be solved in one pass?

Yes.

The solution maintains enough information about previously encountered critical points to calculate both answers immediately.

### Follow-up: Why is `O(1)` space possible?

Because the linked list's structure provides sequential access, and the answer requires only a constant amount of historical information.

## Personal Takeaways

1. When finding distances between special positions, ask whether only adjacent positions matter for the minimum.
2. For maximum span problems, first and last occurrences are often sufficient.
3. Do not automatically store every matching position.
4. Ask whether previous information can be compressed into a few variables.
5. Linked-list problems often become simple once the required local state is identified.
