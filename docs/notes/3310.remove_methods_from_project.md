# Remove Methods From Project

## Problem

- **LeetCode:** 3310
- **Difficulty:** Medium
- **Category:** Graph Traversal (BFS/DFS), Reachability

---

## Core Pattern

**Reachability in a Directed Graph**

### Recognition Cues

- Starting from one node
- Find everything reachable
- Directed dependencies
- Remove all reachable nodes
- Validate incoming edges

---

## Intuition

The suspicious methods form exactly the set of nodes reachable from `k`.

After identifying this set, removal is possible only if there are no incoming edges from outside the suspicious set.

This naturally separates into two phases:

1. Find the suspicious component.
2. Validate whether it can be isolated.

---

## Brute Force

For every node, repeatedly search whether it is reachable from `k`.

Time:

O(n(n+m))

Too slow.

---

## Optimal Solution

### Key Observations

- Suspicious methods are simply all nodes reachable from `k`.
- BFS/DFS finds them in linear time.
- Only one additional scan of all edges is needed.

---

## Algorithm

1. Build adjacency list.
2. BFS/DFS from `k`.
3. Mark all reachable methods.
4. Scan every edge.
5. If an edge enters the suspicious set from outside, return every method.
6. Otherwise return all non-suspicious methods.

---

## Complexity

Time:

O(n+m)

Space:

O(n+m)

---

## Edge Cases

- No edges
- Single node
- Cycles
- Entire graph suspicious
- Disconnected graph
- Multiple incoming edges
- Multiple outgoing edges

---

## Alternative Approaches

- DFS
- BFS

Both have identical complexity.

## Personal Takeaways

- Reachability means graph traversal.
- Do not confuse connectivity with reachability.
- Separate "find component" from "validate component".
- Linear graph traversals are usually enough.
