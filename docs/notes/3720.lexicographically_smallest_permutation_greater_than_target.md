# Lexicographically Smallest Permutation Greater Than Target

## Problem

- **Name:** Lexicographically Smallest Permutation Greater Than Target
- **Difficulty:** Medium
- **Category:** Greedy, Backtracking, Frequency Counting, Lexicographical Ordering

## Core Pattern

### Main Algorithmic Pattern

**Lexicographical construction using greedy choice with limited backtracking**

Construct the answer from left to right while tracking whether the constructed prefix is:

- exactly equal to the corresponding prefix of `target`, or
- already lexicographically greater.

### Recognition Cues

Look for phrases such as:

- "lexicographically smallest"
- "greater than target"
- "permutation of characters"
- "rearrange characters"
- "smallest string satisfying..."
- "smallest permutation"

### Why the Pattern Applies

Lexicographical comparison is determined by the first position where two strings differ.

Therefore, while constructing the answer:

1. Keep the prefix equal to `target` for as long as possible.
2. If equality becomes impossible, make the smallest possible increase.
3. Once the prefix is greater, minimize the remaining suffix.

---

## Intuition

Think about the answer as being constructed from left to right.

There are two important states.

### State 1: Prefix Is Equal

Suppose:

```python
answer[:i] == target[:i]
```

The best candidate is target[i] because matching it keeps the answer as small as possible.

If that character is available, consume it and continue.

However, this choice may eventually lead to a dead end. Therefore, the choice must be reversible.

If the equal path cannot be completed, backtrack and try the smallest available character greater than target[i].

The first such successful choice is optimal.

State 2: Prefix Is Already Greater

Suppose:

```python
answer[:i] > target[:i]
```

The comparison is already decided.

No future character can make the complete string smaller than target.

Therefore, the only remaining objective is:

Make the suffix as small as possible.

So the remaining characters should be consumed in ascending order.

## Brute Force

### Idea

Generate every unique permutation of s.

For every permutation:

1. Check whether it is strictly greater than `target`.
2. Keep the smallest valid permutation.

### Complexity

With n distinct characters there can be:

```text
n!
```

permutations.

Comparing each permutation can take O(n) time.

Therefore the worst-case complexity is:

```text
O(n × n!)
```

### Why It Is Inefficient

Most permutations do not need to be examined.

Lexicographical ordering gives us enough structure to construct the answer directly.

## Optimal Solution

### Key Observations

- Lexicographical comparison depends on the first differing position.
- While the prefix is equal to `target`, matching `target[i]` is preferable.
- If matching eventually fails, we need to increase an earlier position.
- The increase should be as small as possible.
- Once a greater character is selected, the rest should be sorted in ascending order.
- A frequency map is enough because only the remaining character counts matter.

### Data Structures

Use a frequency map:

```python
counts = Counter(s)
```

At most 26 lowercase characters exist, so the alphabet itself is constant-sized.

The recursive path is stored in a mutable list:

```python
ans = []
```

Characters are added and removed using:

```python
ans.append(char)
ans.pop()
```

### Algorithm

1. Count the occurrences of every character in `s`.
2. Start at index `0`.
3. Track whether the constructed prefix is already greater than `target`.
4. If the prefix is equal:
        - Try `target[idx]` if it is available.
        - Temporarily consume it.
        - Recursively attempt to complete the remaining positions.
        - If that fails, restore the character.
        - Then try every available character greater than `target[idx]`, from smallest to largest.
        - If a greater character is selected, mark the state as already greater.
5. Once the prefix is greater, choose the smallest available character and continue until all characters are consumed.
6. When all positions are filled, return success only if the constructed string is strictly greater than `target`.
7. If no valid construction exists, return `""`.

### Complexity

Let n = len(s).

The alphabet has only 26 lowercase characters.

#### Time Complexity

```text
O(26n) = O(n)
```

At each position, only the 26 possible lowercase characters need to be considered.

The recursive search does not enumerate all permutations.

Once the prefix becomes greater than target, the smallest remaining character is always the correct choice.

#### Space Complexity

```text
O(n)
```

The recursion stack can reach depth n, and the answer contains n characters.

The frequency map contains at most 26 entries, which is O(1).

### Edge Cases

#### No Valid Permutation

If target is greater than or equal to every permutation of s, return:

```python
""
```

Example:

```python
s = "abc"
target = "cba"
result = ""
```

#### Target Itself Is a Permutation

Equality is not sufficient because the result must be strictly greater.

Example:

```python
s = "abc"
target = "abc"
result = "acb"
```

#### Target Is Smaller Than Every Possible Permutation

The smallest permutation itself is the answer.

Example:

```python
s = "abc"
target = "aaa"
result = "abc"
```

#### Duplicate Characters

The frequency map must correctly preserve duplicate counts.

Example:

```python
s = "aabc"
```

#### All Characters Are Identical

No greater permutation exists.

Example:

```python
s = "aaaa"
target = "aaaa"
result = ""
```

#### Backtracking Required

An equal choice may look optimal locally but prevent completion later.

The algorithm must restore that choice and try a larger character at the appropriate position.

## Alternative Approaches

### Iterative Next-Permutation Reasoning

The problem can also be solved without recursion.

The key idea is to determine the longest prefix that can remain equal to target, then find the rightmost position where the answer can be increased.

After increasing that position, place the remaining characters in ascending order.

This gives the same underlying strategy:

```text
preserve equality
        |
make smallest possible increase
        |
minimize suffix
```

### Frequency Array

Instead of:

Counter(s)

we can use an array of length 26.

For example:

```python
counts[0] = number of 'a'
counts[1] = number of 'b'
...
counts[25] = number of 'z'
```

This can be slightly more efficient but does not change the asymptotic complexity.

### Full Backtracking

Trying every available character at every position is a general backtracking solution, but it is unnecessary here because lexicographical ordering gives strong pruning.

## Interview Discussion

### Why isn't this ordinary exponential backtracking?

The problem's lexicographical structure drastically restricts useful exploration.

When the prefix is equal to target, the algorithm first tries the equal character.

If that path fails, it tries larger characters in increasing order.

Once a greater prefix is established, there is no reason to explore suffix permutations because the sorted suffix is always optimal.

### Why can we ignore characters smaller than `target[i]`?

If all previous characters are equal and we select:

```python
answer[i] < target[i]
```

then the entire answer is already smaller than target.

No later character can change that comparison.

Therefore, such a choice can never produce a valid answer.

### Why is the first successful greater character optimal?

Suppose the current prefix is equal to target.

If we choose a character larger than target[i], then that position becomes the first differing position.

A smaller increase at this position always produces a lexicographically smaller result than a larger increase.

Therefore, candidates must be considered in ascending order.

### Why can the suffix be greedily minimized?

Once the first differing position makes the answer greater than target, the comparison can no longer change.

Therefore, minimizing the suffix independently gives the smallest complete answer.

### Can the recursion be eliminated?

Yes.

An iterative solution can identify the latest position where the prefix can be increased and then fill the suffix with the smallest remaining characters.

The recursive implementation is nevertheless a clear way to express the equal/greater state.

## Personal Takeaways

- Lexicographical order is controlled by the first differing position.
- When constructing against a target, stay equal for as long as possible.
- When equality becomes impossible, make the smallest feasible increase.
- After becoming greater, greedily minimize everything that follows.
- Frequency counting is ideal when permutations contain duplicate characters.
- Backtracking does not automatically mean exponential complexity; problem structure can make the effective search very small.
