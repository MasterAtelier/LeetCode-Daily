# 3718. Smallest Missing Multiple of K

## Problem

- **Name:** Smallest Missing Multiple of K
- **Difficulty:** Easy
- **Category:** Array, Hash Set, Enumeration

Given an integer array `nums` and an integer `k`, find the smallest
positive multiple of `k` that does not occur in `nums`.

---

## Core Pattern

### Hash Set + Ordered Candidate Enumeration

The core idea is to combine:

1. Fast membership checking using a hash set.
2. Sequential generation of valid candidates.

The possible answers are not arbitrary integers.

They must belong to the sequence:

k, 2k, 3k, 4k, ...

Therefore, generate these candidates in increasing order and return
the first one that is not present.

### Recognition Cues

Look for statements such as:

- "smallest missing"
- "first value not present"
- "check whether values exist"
- candidates follow a predictable sequence
- repeated membership queries
- values need to be tested in increasing order

These often suggest:

Hash Set + Enumeration

---

## Intuition

The important observation is that we do not need to search every
positive integer.

The answer must be a positive multiple of `k`.

Therefore, the candidate space is:

k
2k
3k
4k
...

Now the problem becomes:

"Find the first candidate in this sequence that is not contained in
nums."

If we repeatedly search the original array, every membership check
costs O(n).

Instead, convert `nums` into a hash set.

This makes membership checks O(1) on average.

Because candidates are checked in strictly increasing order, the first
missing candidate is guaranteed to be the smallest missing multiple.

---

## Brute Force

### Idea

Start with `k`.

For every candidate:

k, 2k, 3k, ...

scan the entire `nums` array to determine whether the candidate exists.

If it exists, move to the next multiple.

Otherwise, return it.

### Complexity

If we examine `m` multiples before finding the answer:

Time:

O(n * m)

In the worst relevant case, `m` can be proportional to `n`, giving:

O(n²)

Space:

O(1)

### Why It Is Inefficient

The same array is scanned repeatedly.

The operation we repeatedly need is:

"Does this number exist?"

A hash set is better suited for repeated membership queries.

---

## Optimal Solution

### Key Observations

1. The answer must be a positive multiple of `k`.
2. Positive multiples have a natural increasing order.
3. We only need to know whether each candidate exists.
4. A hash set provides O(1) average membership lookup.
5. The first missing candidate is automatically the minimum answer.

### Data Structures Used

Hash Set

The set stores all values from `nums`.

This changes membership testing from O(n) to O(1) average time.

---

## Algorithm

1. Insert every element of `nums` into a hash set.
2. Initialize the candidate to `k`.
3. Check whether the candidate exists in the set.
4. If it exists, move to the next multiple by adding `k`.
5. Repeat until a candidate does not exist.
6. Return that candidate.

---

## Complexity

Let `n` be the number of elements in `nums`.

Creating the hash set requires:

O(n)

At most O(n) relevant multiples can be present before finding a
missing one.

Each hash-set lookup takes O(1) average time.

Therefore:

### Time Complexity

O(n)

### Space Complexity

O(n)

The hash set can contain all elements of `nums`.

---

## Edge Cases

### First multiple is missing

nums = [1, 4, 7]
k = 5

The first candidate `5` is already missing.

Answer:

5

### Several consecutive multiples exist

nums = [2, 4, 6, 8]
k = 2

Candidates:

2 -> present
4 -> present
6 -> present
8 -> present
10 -> missing

Answer:

10

### Gap between multiples

nums = [3, 6, 12]
k = 3

Candidates:

3 -> present
6 -> present
9 -> missing

Answer:

9

### k = 1

Every positive integer is a multiple of 1.

The problem becomes finding the first missing positive integer starting
from 1.

### Answer exceeds values allowed inside nums

If:

nums = [100]
k = 100

then:

100 -> present
200 -> missing

The answer is 200 even though input values are bounded by 100.

---

## Alternative Approaches

### Linear Search for Every Candidate

Generate:

k, 2k, 3k, ...

and search `nums` directly.

Advantages:

- O(1) extra space
- simple implementation

Disadvantage:

- repeated O(n) membership searches
- potentially O(n²) time

The hash-set approach is preferable.

### Boolean Presence Array

Because the input values are tightly bounded, a boolean array could
also represent whether each value exists.

Advantages:

- deterministic O(1) lookup
- low constant factors

Disadvantages:

- relies on known value constraints
- less general than a hash set

The hash-set solution naturally generalizes to larger value ranges.
