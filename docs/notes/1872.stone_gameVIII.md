1872 — Stone Game VIII

Problem

Name: Stone Game VIII

Difficulty: Hard

Category: Dynamic Programming / Game Theory / Prefix Sum

LeetCode: 1872

The game allows a player to remove at least two leftmost stones, score their sum, and replace those stones with a single stone containing that sum. Alice maximizes the final score difference and Bob minimizes it. The constraints allow up to 10^5 stones. citeturn0search0

Core Pattern

Primary pattern: Prefix Sum + Minimax Dynamic Programming.

The important reduction is that after a move, the remaining state is completely determined by a prefix sum and the untouched suffix. This lets the game be represented as a one-dimensional recurrence rather than a general game-state DP.

Recognition cues

Look for:

Two-player optimal-play / score-difference problems.

A move that always consumes a prefix.

The consumed values being replaced by their sum.

A state that can be represented by a prefix sum.

A need to maximize the current player's advantage against optimal opposition.

Why the pattern applies

If a player chooses the first k stones, the score gained is exactly prefix[k - 1]. The resulting game starts with that prefix sum followed by the untouched suffix. Therefore, every possible first move maps naturally to a prefix-sum state.

Intuition

The key observation is that we do not need to simulate the sequence of physical stone merges.

After Alice chooses a prefix ending at index i, the first stone of the new state is prefix[i]. From that point onward, the opponent's optimal result can be represented by a single value.

Let best represent the best score difference achievable from the relevant suffix state.

If we choose prefix prefix[i], the current player gains prefix[i], but the opponent then gets the advantage represented by best. Therefore:

candidate = prefix[i] - best

We want the maximum candidate, so:

best = max(best, prefix[i] - best)

The final prefix sum is the initial state in which Alice can take all stones, so initialize:

best = prefix[n - 1]

Then process candidate prefixes from right to left.

This turns what looks like a large game-tree problem into a linear DP.

Brute Force

Idea

For every state, try every legal choice x from 2 through the current number of stones. Compute the prefix sum of the removed stones, create the resulting state, and recursively compute the opponent's optimal score difference.

Complexity

The number of game states grows exponentially in the worst case, because every state can branch into many possible moves.

A memoized implementation is still far too expensive for n = 10^5.

Why it is inefficient

The same structural game decisions can be represented much more compactly by prefix sums. The recurrence removes the need to construct and memoize entire tuple states.

Optimal Solution

Key observations

Every legal move consumes a prefix.

The score of that move is the corresponding prefix sum.

The replacement stone is exactly that prefix sum.

Therefore, the resulting game can be described using prefix sums.

The alternating nature of the game gives a minimax recurrence:
current advantage = chosen prefix - opponent advantage.

Only the best value from the next state is required, so a single scalar is enough.

Data structures used

The input list itself is transformed into prefix sums.

One scalar, best, stores the DP state.

Algorithm explanation

Convert stones into prefix sums in-place.

Initialize best to the total sum.

Iterate through possible prefix endpoints from n - 2 down to 1.

For each prefix sum, compute the score difference obtained by taking that prefix:
prefix[i] - best.

Keep the better of the existing best and this candidate.

Return best.

The submitted implementation matches this recurrence.

Algorithm

Compute all prefix sums in stones.

Set best to the total sum.

Starting at the second-last prefix, move toward the second prefix.

Update best with the larger of:

the current best;

current prefix sum minus best.

Return best.

Complexity

Time: O(n)

One pass builds prefix sums.

One reverse pass performs the DP.

Extra Space: O(1)

The input list is modified in place.

Input mutation: The implementation mutates stones into its prefix-sum representation. This is accepted by LeetCode, but should be documented or avoided with stones.copy() if callers need the original list.

The constraints have n <= 10^5, so the linear solution is appropriate. citeturn0search0

Edge Cases

n = 2: there is exactly one legal move; return the sum of both stones.

All negative values: taking all stones may be unavoidable or optimal despite producing a negative score difference.

All positive values: taking the entire array can be optimal.

Zeros: score differences can be exactly zero.

Mixed positive and negative values: greedy selection of the largest immediate prefix is not sufficient; the minimax recurrence is required.

Large n: the implementation remains linear and uses constant auxiliary space.

Alternative Approaches

1. Full game-state recursion

Correct for very small inputs, but the state space grows rapidly and cannot handle 10^5 elements.

2. Memoized minimax over complete states

Improves repeated-state work but still represents much more information than necessary. The prefix-sum structure allows the state to collapse to a scalar recurrence.

3. Prefix sums + one-dimensional DP array

An explicit DP array can make the recurrence easier to visualize, but it is unnecessary. Since each state only needs the immediately maintained best value, the array can be compressed to O(1) extra space.

Interview Discussion

Why can the game be reduced to prefix sums?

Every move removes a prefix and replaces it with that prefix's sum. Therefore, the exact individual values inside that removed prefix no longer matter after the move.

Why is the recurrence prefix[i] - best?

The current player receives prefix[i]. The opponent then plays the resulting game optimally, so the current player's net advantage is their immediate gain minus the opponent's optimal advantage.

Why start with the total sum?

Taking all stones is always a legal first move. It leaves one stone and ends the game immediately, so its score difference is simply the total prefix sum.

Can this be solved with ordinary greedy?

No. A locally largest prefix is not necessarily globally optimal because the chosen prefix changes the state available to the opponent.

Why process from right to left?

A state based on a prefix depends on the optimal result of a later/smaller suffix state. Reverse iteration ensures that the required best value has already been computed.

Personal Takeaways

When a game consumes prefixes, immediately ask whether prefix sums collapse the state.

For score-difference games, think my_gain - opponent_best.

A large game tree can sometimes collapse to one-dimensional DP when the resulting state has a compact representation.

Reverse iteration is often a clue that a DP state depends on a later state.

In-place prefix sums can reduce auxiliary space from O(n) to O(1), at the cost of mutating input.
