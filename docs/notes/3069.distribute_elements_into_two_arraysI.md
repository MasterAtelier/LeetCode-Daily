# Distribute Elements Into Two Arrays I

## Problem

- **Name:** Distribute Elements Into Two Arrays I
- **Difficulty:** Easy
- **Category:** Array

## Core Pattern

### Main algorithmic pattern
Simulation with two dynamically built arrays.

### Recognition cues
- The problem explicitly describes how each incoming element should be distributed.
- The decision depends only on the current last element of each array.
- The original order of elements must be preserved.

### Why the pattern applies
At every step, the problem gives a deterministic rule for choosing between `arr1` and `arr2`. There is no need for sorting, searching, or dynamic programming; direct simulation is sufficient.

## Intuition

Start with the first element in `arr1` and the second element in `arr2`. For every remaining element, compare the last elements of the two arrays. If the last element of `arr1` is larger, append to `arr1`; otherwise append to `arr2`.

After processing every element, concatenate `arr2` to `arr1`.

The important interview insight is to translate the statement's distribution rule directly into a loop while preserving the input order.

## Brute Force

There is no meaningful separate brute-force approach because the required distribution can be simulated directly.

A direct simulation is already optimal.

## Optimal Solution

### Key observations

1. The first element always starts `arr1`.
2. The second element always starts `arr2`.
3. Every subsequent element is assigned using only `arr1[-1]` and `arr2[-1]`.
4. The arrays can be constructed incrementally.
5. The final answer is `arr1 + arr2`.

### Data structures used

- Two Python lists.

### Algorithm explanation

Initialize:

- `arr1 = [nums[0]]`
- `arr2 = [nums[1]]`

For every `nums[i]` from index `2` onward:

- If `arr1[-1] > arr2[-1]`, append it to `arr1`.
- Otherwise, append it to `arr2`.

Finally, extend `arr1` with all elements of `arr2` and return `arr1`.

## Algorithm

1. Create `arr1` containing the first element.
2. Create `arr2` containing the second element.
3. Iterate through the remaining elements.
4. Compare the last element of `arr1` with the last element of `arr2`.
5. Append the current element to the appropriate array.
6. Append all elements of `arr2` after `arr1`.
7. Return the resulting array.

## Complexity

- **Time Complexity:** `O(n)`
  - Every input element is processed once.
  - The final `extend` also takes linear time.
- **Space Complexity:** `O(n)`
  - The two arrays together contain all `n` elements.

## Edge Cases

- `nums` contains exactly two elements.
- Several consecutive elements are equal.
- All elements are increasing.
- All elements are decreasing.
- Negative values are present.
- One array receives almost all subsequent elements.
- Elements are duplicated.

## Alternative Approaches

### Building a separate result list
Instead of extending `arr1`, a separate result could be created using `arr1 + arr2`. This is still `O(n)` time and `O(n)` additional output space.

### In-place variants
An in-place approach is unnecessary because the two intermediate arrays are part of the natural simulation of the problem.

## Python Tips

- `arr1[-1]` accesses the last element of a list in `O(1)`.
- `list.append()` is amortized `O(1)`.
- `list.extend(other)` efficiently appends all elements from another iterable.
- Iterating over `nums[2:]` is readable, although it creates a slice; for strict `O(1)` auxiliary iteration space, use an index-based loop as in the submitted solution.

## Interview Discussion

An interviewer may ask:

### Why is sorting unnecessary?
Because the distribution rule depends on the current last elements, not on global ordering.

### Can this be done in one pass?
Yes. The submitted solution processes each element once.

### What happens when the last elements are equal?
The `else` branch sends the element to `arr2`, exactly as required.

### Can the result be returned without mutating `arr1`?
Yes, `arr1 + arr2` can be returned. The current `extend` approach is also valid.

## Personal Takeaways

1. Follow the problem's distribution rule literally before looking for a more complicated algorithm.
2. When only the most recent element matters, keep direct references to the current ends.
3. Simulation can be asymptotically optimal.
4. Always check equality behavior because `>` versus `>=` changes the destination array.
5. Preserve input order when the problem specifies sequential distribution.
