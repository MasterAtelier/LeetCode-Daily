# Find the Lexicographically Smallest Valid Sequence

## Problem

- Name: Find the Lexicographically Smallest Valid Sequence
- Difficulty: Medium
- Category: Greedy, String, Subsequence

## Core Pattern

### Main Pattern

Greedy subsequence construction with suffix feasibility preprocessing.

### Recognition Cues

- Need to construct a subsequence.
- The result must be lexicographically smallest.
- There is a limited number of allowed deviations/mismatches.
- A greedy choice must be made only when the remaining suffix is still feasible.

### Why the Pattern Applies

For a lexicographically smallest index sequence, we want the earliest possible index at every position.

However, when the current character does not match, we can spend the one allowed mismatch only if the remaining characters can still match exactly.

A suffix feasibility array lets us make this decision in O(1).

## Intuition

There are two things to optimize:

1. Use the smallest possible index at every position.
2. Never make a choice that makes completing `word2` impossible.

Process `word1` from left to right.

If the current character matches the next required character in `word2`, take it immediately.

If it does not match, we may use our single mismatch. But before doing so, verify that the remainder of `word2` can be matched by the remainder of `word1`.

The suffix preprocessing provides exactly this feasibility information.

## Brute Force

Try every subsequence of `word1` having length `len(word2)`.

For every subsequence:

1. Compare it with `word2`.
2. Count mismatches.
3. Keep sequences having at most one mismatch.
4. Return the lexicographically smallest index sequence.

### Complexity

There are O(2^n) subsequences in general, making this approach exponential.

It is unsuitable for the problem constraints.

## Optimal Solution

### Key Observations

1. The answer is a subsequence of `word1`.
2. At most one selected character may differ from the corresponding character in `word2`.
3. We want the lexicographically smallest sequence of indices.
4. Therefore, at every position, we should select the earliest feasible index.
5. If a mismatch is considered, we need to know whether the rest of `word2` can still be matched exactly.

### Suffix Feasibility

Build `suf[i]`.

It represents the earliest position of `word2` that remains unmatched after greedily matching the suffix `word1[i:]` against the end of `word2`.

Equivalently, it allows us to determine whether:

`word2[j+1:]`

can be matched exactly inside:

`word1[i+1:]`

The condition is:

`suf[i + 1] <= j + 1`

If true, the current position can safely be used as the one mismatch.

## Algorithm

1. Let `j = m - 1`.
2. Traverse `word1` from right to left.
3. Greedily match characters against `word2` from right to left.
4. Store the earliest still-unmatched position in `suf[i]`.
5. Traverse `word1` from left to right.
6. Maintain `j`, the next character required from `word2`.
7. If `word1[i] == word2[j]`, select `i`.
8. Otherwise, if the mismatch has not been used and the suffix feasibility condition holds, select `i` and mark the mismatch as used.
9. Stop once all characters of `word2` have been selected.
10. If all `m` characters were selected, return the answer; otherwise return an empty sequence.

## Complexity

### Time Complexity

`O(n)`

The suffix preprocessing scans `word1` once and the greedy construction scans it once.

### Space Complexity

`O(n)`

The suffix array requires `O(n)` space.

## Edge Cases

- `word1` and `word2` have equal length.
- `word1 == word2`.
- The answer requires exactly one mismatch.
- The answer requires zero mismatches.
- No valid sequence exists.
- The mismatch occurs at the first selected character.
- The mismatch occurs at the last selected character.
- Repeated characters create multiple possible subsequences.
- `word2` is much shorter than `word1`.

## Alternative Approaches

### Brute Force

Enumerate all subsequences.

Correct but exponential.

### Dynamic Programming

A DP formulation can track whether zero or one mismatch has been used.

However, the greedy + suffix-feasibility solution is simpler and achieves O(n).

### Greedy Without Suffix Feasibility

Simply taking the first possible mismatch is incorrect because that mismatch might make the remaining target impossible.

The suffix array is what makes the greedy decision safe.

## Python Tips

- `range(n - 1, -1, -1)` is useful for right-to-left preprocessing.
- Lists provide O(1) indexed access and are appropriate for the suffix array.
- Keep state variables such as `j` and `used_mismatch` explicit; this makes the greedy invariant easy to understand.

## Interview Discussion

An interviewer may ask:

### Why can you always take an exact match immediately?

Because we are minimizing the index sequence lexicographically. If the current index can satisfy the next required character exactly, taking it is the earliest possible valid choice and preserves the mismatch for later if needed.

### Why is the suffix condition necessary?

A mismatch can only be used if the remainder can still be matched exactly.

The suffix array answers that feasibility question in O(1).

### Why is the solution O(n)?

Both the right-to-left preprocessing and left-to-right greedy scan are linear.

## Personal Takeaways

1. Lexicographically smallest subsequence problems often require choosing the earliest feasible position.
2. Greedy choices need a feasibility check before they are safe.
3. Precompute suffix information when future feasibility needs to be queried repeatedly.
4. A limited number of mismatches can often be represented with a small state such as `used_mismatch`.
5. The combination of greedy construction + feasibility preprocessing can turn an exponential subsequence problem into O(n).
