# Stone Game II

## Problem

* **Name:** Stone Game II
* **LeetCode:** 1140
* **Difficulty:** Medium
* **Category:** Dynamic Programming / Game Theory

## Core Pattern

**Game DP with Minimax + Suffix Sum**

The state is determined by:

* `i` — the first pile that has not been taken.
* `M` — the current maximum allowed take size.

From a state `(i, M)`, the current player may take between `1` and `2M` piles.

The existing repository already treats game problems using minimax-style dynamic programming. Stone Game II is a significant variation because the game state contains an additional dynamic parameter `M`, which controls the legal moves.

## Recognition Cues

Look for:

* Two players alternating turns.
* Both players play optimally.
* Players take a variable number of elements.
* The legal move range depends on the previous move.
* The remaining input is a suffix of the original array.
* The objective is to maximize the number of points/stones collected.

A particularly important signal is:

> "You can take from 1 to 2M elements, then M becomes max(M, X)."

That tells us the previous move affects the future state, so `M` must be part of the DP state.

## Intuition

Instead of trying to simulate both players explicitly, define the DP from the perspective of **whoever's turn it currently is**.

For a state `(i, M)`:

1. There are `suffix[i]` stones remaining.
2. The current player chooses `X`.
3. After taking `X`, the opponent receives the state `(i + X, max(M, X))`.
4. If the opponent can obtain `solve(i + X, new_M)`, then the current player gets:

   `suffix[i] - solve(i + X, new_M)`

Therefore:

`solve(i, M) = max(suffix[i] - solve(i + X, new_M))`

over all legal choices of `X`.

This is the key minimax transformation:

> **My maximum score = total remaining score − opponent's maximum score.**

## Brute Force

### Idea

Recursively try every possible number of piles the current player can take.

For every choice:

* Calculate the stones taken.
* Recursively solve the opponent's state.
* Choose the move producing the largest final score.

### Complexity

Without memoization, the same states are repeatedly explored, producing exponential time complexity.

### Why It Is Inefficient

Different sequences of previous moves can lead to the same `(i, M)` state.

Once we recognize that `(i, M)` completely determines the future game, those repeated states should be cached.

## Optimal Solution

### Key Observations

1. The future does not depend on how we arrived at a state.
2. The future is completely determined by `(i, M)`.
3. Suffix sums let us calculate the total remaining stones in `O(1)`.
4. The opponent's optimal score can be subtracted from the total remaining stones.
5. If `2M` is large enough to take all remaining piles, the current player takes everything immediately.

### Data Structures

* Suffix-sum array.
* Hash map for memoization.

### Algorithm Explanation

For each state `(i, M)`:

1. If `2M >= n - i`, return all remaining stones.

2. Check whether `(i, M)` has already been computed.

3. Try every legal `X` from `1` through `2M`.

4. Update:

   `new_M = max(M, X)`

5. The opponent's best score is:

   `solve(i + X, new_M)`

6. Therefore the current player's score is:

   `suffix[i] - solve(i + X, new_M)`.

7. Keep the maximum.

8. Memoize the result.

## Algorithm

1. Build `suffix` where `suffix[i]` represents the total stones from `i` to the end.
2. Define `solve(i, M)` as the maximum stones the current player can obtain.
3. If all remaining piles can be taken, return `suffix[i]`.
4. If `(i, M)` is cached, return the cached value.
5. Iterate over every legal number of piles `X`.
6. Calculate the new value of `M`.
7. Subtract the opponent's optimal result from the total remaining stones.
8. Keep the maximum result.
9. Cache and return it.
10. Start with `solve(0, 1)`.

## Complexity

Let `n` be the number of piles.

### Time

There are `O(n²)` possible `(i, M)` states.

Each state can examine up to `O(n)` choices.

Therefore:

**Time: `O(n³)`**

### Space

The memoization table contains `O(n²)` states.

The suffix array requires `O(n)` additional space.

Therefore:

**Space: `O(n²)`**

## Edge Cases

### One pile

```text
[5]
```

The first player can take it immediately.

Result:

```text
5
```

### Two piles

The initial `M = 1`, so the player may take both piles because `2M = 2`.

### All remaining piles are available

When:

```text
2M >= remaining_piles
```

the current player should immediately take everything.

### Unequal pile values

Greedy selection of the largest immediate pile is not necessarily optimal because taking more piles changes `M` and therefore changes future choices.

## Alternative Approaches

### Bottom-Up DP

The same state `(i, M)` can be computed iteratively rather than recursively.

Advantages:

* Avoids recursion.
* Makes state transitions explicit.

Disadvantages:

* More cumbersome state-order management.
* The recursive formulation maps more naturally to the game structure.

### Difference-of-Scores DP

Another common formulation stores:

`current_player_score - opponent_score`

rather than the current player's absolute score.

This can eliminate the explicit suffix-total subtraction, but the underlying minimax state is the same.

## Python Tips

* A dictionary is convenient for memoizing tuple states:

  `dp[(i, M)]`

* A suffix array allows constant-time retrieval of the total remaining sum.

* Tuple keys make multi-dimensional memoization straightforward.

* The `max()` function cleanly expresses the current player's optimal choice.

* Python's `@functools.cache` could replace the explicit dictionary if desired.

## Interview Discussion

### Why is `M` part of the DP state?

Because the legal moves depend on `M`. Two states at the same index can have different available moves if their `M` values differ.

### Why subtract the opponent's score?

Because the total number of remaining stones is fixed.

If the opponent obtains `X`, the current player obtains:

`total_remaining - X`.

This converts the two-player minimax problem into a single-player maximization recurrence.

### Why can we return `suffix[i]` immediately?

If `2M` is at least the number of remaining piles, the current player is allowed to take every remaining pile.

### Could we greedily take the largest available pile?

No.

The number of piles taken affects `M`, which affects future move availability. Therefore the immediate gain does not fully determine the optimal move.

## Personal Takeaways

1. **In game DP, define the state from the current player's perspective.**
2. **If the total remaining reward is fixed, `my_score = total - opponent_score` is a powerful minimax transformation.**
3. **Every variable that changes future legal moves belongs in the DP state.**
4. **Suffix sums are useful when every state operates on a suffix of an array.**
5. **Before optimizing a game DP, ask: "Does the current state completely determine the future?"**
